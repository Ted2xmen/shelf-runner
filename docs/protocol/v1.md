# shelf-runner protocol v1

This is the single human-readable description of protocol v1. The code is the source of truth:
every rule below names the line that implements it (see [Sources](#sources)). The machine-checked
examples are in [`fixtures/protocol/v1/`](../../fixtures/protocol/v1/). Version rules are in
[README.md](README.md).

Words used here:

- **runner**: shelf-runner, this repo.
- **producer**: whoever writes queue lines and sends signed commands. Today that is the Shelf app
  (the other end of the contract) or a person using the `shelf-runner line` CLI.
- **consumer**: any process that reads the runner's status or log replies. Shelf reads and writes;
  [Runner Desk](https://github.com/Ted2xmen/runner-desk) only reads.
- **key**: the 32-byte pairing key from `shelf-runner pair`.

## 1. Scope

Protocol v1 covers everything that crosses the runner's process boundary:

- the two Markdown files the runner reads in each enabled folder, `AGENT-QUEUE.md` and
  `SCHEDULED.md` (`Sources/ShelfRunnerCore/QueueLine.swift:59`, `Sources/ShelfRunnerCore/Schedule.swift:92`);
- the canonical text and HMAC signatures of lines and commands;
- the pairing code;
- the macOS distributed notifications: status, ping, commands, log reply
  (`Sources/ShelfRunnerCore/Protocol.swift:7-15`);
- the `heartbeat.json` status copy, the `attach` `.command` files, and the click on a runner
  notification.

It does not cover the runner's private state files (`runs.jsonl`, `approvals.json` and so on).
Those are listed in [ARCHITECTURE.md](../ARCHITECTURE.md) and may change at any time.

## 2. Channels

| Channel | Producer | Consumer | Transport | Security |
|---|---|---|---|---|
| Queue file `AGENT-QUEUE.md` | Shelf, a person (CLI `line` + editor) | runner | file in an enabled folder, watched with FSEvents | per-line HMAC (`sig:`), then one approval per id ([5](#5-canonical-text-and-signatures)) |
| Scheduled file `SCHEDULED.md` | a person (no signer exists today, see [16](#16-known-gaps)) | runner | file in an enabled folder | same as the queue file |
| Pairing code `SR1-...` | runner (`shelf-runner pair`) | the signing app | the user copies it by hand | secret; whoever has it can sign |
| Status `dev.ted2xmen.shelf-runner.status` | runner | Shelf, Runner Desk, anyone | distributed notification, `object: nil`, `userInfo {v, json}`, `deliverImmediately: true` | none: not signed, readable by any process |
| `heartbeat.json` | runner | file readers | copy of the last status JSON in the state dir | file permissions only |
| Ping `dev.ted2xmen.shelf.ping` | any consumer | runner | distributed notification, `object: "dev.ted2xmen.shelf"` | none |
| Commands `dev.ted2xmen.shelf-runner.cmd.<verb>.<id\|->.<ts>.<sig16>` | Shelf | runner | distributed notification, `object: "dev.ted2xmen.shelf"`, no `userInfo` needed | HMAC over `cmd\|verb\|id\|ts`, 60 s window, replay check |
| Log reply `dev.ted2xmen.shelf-runner.log` | runner | the app that asked | distributed notification, `object: nil`, `userInfo {v, id, json}` | none: not signed |
| Attach `attach/<id>.command` | runner | Terminal | 0700 shell script in the state dir, opened with `open -a Terminal` | written and opened by the runner itself |
| Notification click `runnerdesk://job/<id>` | runner | Runner Desk, else Shelf | URL open or app launch | none |

Sources: status post `Sources/ShelfRunnerCore/Bridge.swift:19-21` and `:64`; heartbeat
`Sources/ShelfRunnerCore/Bridge.swift:65`; ping and command observer
`Sources/ShelfRunnerCore/Bridge.swift:31` and `:68-90`; log reply
`Sources/ShelfRunnerCore/Bridge.swift:114`; attach `Sources/ShelfRunnerCore/Attach.swift:24-43`;
click `Sources/shelf-runner/AppNotifier.swift:55-77`.

**The `object` filter.** The runner observes `name: nil` with `object: "dev.ted2xmen.shelf"`,
because macOS does not deliver to a fully unfiltered observer
(`Sources/ShelfRunnerCore/Protocol.swift:12-15`, `Sources/ShelfRunnerCore/Bridge.swift:30-31`).
The `object` is only a channel filter. Any process can post with it; the security of a command is
its signature. A read-only consumer such as Runner Desk also posts its ping with this `object`,
or the runner would never see it.

## 3. Queue lines (AGENT-QUEUE.md)

### Grammar

A task line matches `^- \[([ xX])\] (.*)$` (`Sources/ShelfRunnerCore/QueueLine.swift:66`). Any other
line is not a task line and is ignored (`Sources/ShelfRunnerCore/QueueLine.swift:95-97`). A
trailing `\r` is removed first (`Sources/ShelfRunnerCore/QueueLine.swift:79`).

The rest of the line is split on spaces and tabs into tokens
(`Sources/ShelfRunnerCore/QueueLine.swift:101`). A token `key:value` whose key is in the closed list
`id agent mode ref out by sig` is a key (`Sources/ShelfRunnerCore/QueueLine.swift:60`). Every other
token, including any other `x:y`, stays in the title (`Sources/ShelfRunnerCore/QueueLine.swift:102-104`).
Keys may appear anywhere in the line, before, inside or after the title words.

| Key | Required | Rule | Source |
|---|---|---|---|
| `id:` | yes | `^q-[0-9]{8}T[0-9]{4}-[0-9a-f]{4}$` (CLI makes it from local time + 4 random hex) | `QueueLine.swift:63`, `:112-113`; `Security.swift:133-141` |
| `agent:` | yes | `claude` or `codex` | `QueueLine.swift:8`, `:114-115` |
| `mode:` | no | `attended` (default) or `unattended` | `QueueLine.swift:9`, `:116-117` |
| `ref:` | no | `^[^@\s]+@[0-9a-f]{8}$`: a path, `@`, 8 lowercase hex | `QueueLine.swift:64`, `:118` |
| `out:` | no | any non-empty value; checked as a path later | `QueueLine.swift:123`; `Security.swift:123` |
| `by:` | no | any non-empty value; not signed | `QueueLine.swift:123` |
| `sig:` | no for the grammar, yes to run | `^[0-9a-f]{8}$` | `QueueLine.swift:65`, `:119` |

(Paths in this table are under `Sources/ShelfRunnerCore/`.)

A line is invalid (reported by `list`, never run) when:

- a key has an empty value, such as `id:` (`Sources/ShelfRunnerCore/QueueLine.swift:108`);
- a key appears twice (`Sources/ShelfRunnerCore/QueueLine.swift:109`);
- `id` or `agent` is missing, or any value breaks its rule (`Sources/ShelfRunnerCore/QueueLine.swift:112-119`);
- the title is empty after the keys are removed (`Sources/ShelfRunnerCore/QueueLine.swift:120-121`);
- its `id` was already used by an earlier line of the same file (`Sources/ShelfRunnerCore/QueueLine.swift:84-86`).

**Partial last line.** If the file does not end in a newline, the text after the last newline is
ignored: it may be half written (`Sources/ShelfRunnerCore/QueueLine.swift:70-74`).

### `ref:` escapes

The path part of `ref:` may not contain a raw space or `@`. It has exactly three escapes:
`%20` (space), `%40` (`@`), `%25` (`%`) (`Sources/ShelfRunnerCore/Security.swift:87-88`). The runner
decodes them in one left-to-right pass, so `%2520` is the text `%20`; any other `%` makes the path
invalid (`Sources/ShelfRunnerCore/Security.swift:90-103`). Decoding is only for the path check; the
status echoes `ref` exactly as written (`Sources/ShelfRunnerCore/Security.swift:91`,
`Sources/ShelfRunnerCore/StatusBuilder.swift:102-103`). The runner never computes the hash after
`@`.

### Paths

`out:` and the decoded `ref:` path must be relative, must not start with `/` or `~`, must not
contain `..`, and must resolve (symlinks included, through the nearest existing ancestor) inside the
folder (`Sources/ShelfRunnerCore/Security.swift:65-82`, `:105-108`). A line that breaks this becomes
`failed:path` ([5](#5-canonical-text-and-signatures)).

### Ticks and deletion

- The tick is not signed. A ticked line (`[x]` or `[X]`) is valid but never starts
  (`Sources/ShelfRunnerCore/QueueLine.swift:98`, `Sources/ShelfRunnerCore/Supervisor.swift:209`).
- Ticking or deleting the line of a **running** job stops it: the runner writes a stop marker and
  sends Esc, then Ctrl-C twice 0.3 s apart (`Sources/ShelfRunnerCore/Supervisor.swift:157-159`,
  `Sources/ShelfRunnerCore/Agent.swift:162-166`, `Sources/ShelfRunnerCore/Tmux.swift:108-120`). If
  the job is still running after `cancel_grace_seconds` (default 60), the runner closes the tmux
  window (`Sources/ShelfRunnerCore/Supervisor.swift:151-155`, `Sources/ShelfRunnerCore/Supervisor.swift:7`).
  The final state is `cancelled`.
- Ticking or deleting the line of a **pending** job (`queued`, `needs-approval`, `waiting:*`) makes
  it `cancelled` (`Sources/ShelfRunnerCore/Supervisor.swift:172-173`).
- A missing or unreadable file cancels nothing (`Sources/ShelfRunnerCore/Supervisor.swift:88`,
  `:128-132`).

The runner never writes the queue file (`Sources/ShelfRunnerCore/Paths.swift:3-4`).

## 4. Scheduled lines (SCHEDULED.md)

Same tokens and rules as the queue, with these differences
(`Sources/ShelfRunnerCore/Schedule.swift:89-161`):

- **No checkbox.** An item is `- <text>` that does not start with `[ ] `, `[x] ` or `[X] `
  (`Sources/ShelfRunnerCore/Schedule.swift:95`).
- **A bullet with no key at all is a note**, not an item (`Sources/ShelfRunnerCore/Schedule.swift:119`, `:137`).
- **Extra keys** `due:`, `at:`, `every:` (`Sources/ShelfRunnerCore/Schedule.swift:93`).
- **`id:`** is `^s-[0-9]{8}T[0-9]{4}-[0-9a-f]{4}$` (`Sources/ShelfRunnerCore/Protocol.swift:101-103`,
  `Sources/ShelfRunnerCore/Schedule.swift:140`). One id covers every occurrence
  (`Sources/ShelfRunnerCore/Protocol.swift:105`).
- **`mode:unattended` is required**; a missing or other mode is invalid
  (`Sources/ShelfRunnerCore/Schedule.swift:143-144`).
- **`due:`** is required, `yyyy-MM-dd`, and must be a real calendar day (`2026-02-30` is invalid)
  (`Sources/ShelfRunnerCore/Schedule.swift:14-21`, `:145`, `:152`).
- **`at:`** is optional, `HH:MM`, 00-23 and 00-59, local wall time; without it the time is 00:00
  (`Sources/ShelfRunnerCore/Schedule.swift:10`, `:23-29`, `:153`).
- **`every:`** is optional: `day`, `week`, `month` or `year`; without it the line runs once
  (`Sources/ShelfRunnerCore/Schedule.swift:6`, `:146-150`). A month or year step clamps to the last
  day of a shorter month and stays clamped (Jan 31, Feb 28, Mar 28)
  (`Sources/ShelfRunnerCore/Schedule.swift:38-48`).

**Runs.** A scheduled line passes the same gate as a queue line on first sight
([5](#5-canonical-text-and-signatures)); after approval it runs once per occurrence
(`Sources/ShelfRunnerCore/Supervisor.swift:220-259`). Between occurrences the job is in the
runner-internal state `scheduled`, which never appears in `jobs`; the line is listed under
`scheduled` in the status instead (`Sources/ShelfRunnerCore/Supervisor.swift:66-68`,
`Sources/ShelfRunnerCore/StatusBuilder.swift:88`, `:122-136`). Occurrences are matched by local wall
clock, so a time zone change neither repeats nor misses one
(`Sources/ShelfRunnerCore/Schedule.swift:58-67`).

**Missed.** An occurrence first seen more than `missed_after_minutes` (default 60) after its time is
recorded as `missed` with a notification, and does not run
(`Sources/ShelfRunnerCore/Supervisor.swift:20`, `:238-251`). A line written after its own due time
is not missed; it waits for the next occurrence (`Sources/ShelfRunnerCore/Supervisor.swift:240-246`).

**Stopping.** Removing the line stops a running occurrence and cancels a pending one, as in the
queue (`Sources/ShelfRunnerCore/Supervisor.swift:128-132`, `:157-159`, `:172-173`).

## 5. Canonical text and signatures

### Canonical title

1. Take the title: the line's tokens without the closed-list keys, joined with one space
   (`Sources/ShelfRunnerCore/QueueLine.swift:120`, `Sources/ShelfRunnerCore/Schedule.swift:156`).
2. Split on whitespace runs, join with one space (`Sources/ShelfRunnerCore/Protocol.swift:30-32`).
   "Whitespace" is Swift's `Character.isWhitespace` (Unicode White_Space), not only ASCII space and
   tab.
3. Convert to NFC (`Sources/ShelfRunnerCore/Protocol.swift:32`).

### Canonical text

Lines are joined with `\n`, no trailing newline.

Queue line, 6 lines (`Sources/ShelfRunnerCore/Protocol.swift:35-37`):

```text
q1
<id>
<folder>
<canonical title>
<agent>
<mode>
```

Scheduled line, 9 lines; a missing `at:` or `every:` is an empty line
(`Sources/ShelfRunnerCore/Protocol.swift:39-43`):

```text
s1
<id>
<folder>
<canonical title>
<agent>
<mode>
<due>
<at or empty>
<every or empty>
```

- `<folder>` is the folder's `realpath(3)` (so `/tmp` is `/private/tmp`), the same string the runner
  stores when the folder is enabled (`Sources/ShelfRunnerCore/Folders.swift:26-39`,
  `Sources/ShelfRunnerCore/Agent.swift:62`). A line copied to another folder no longer verifies.
- `<mode>` is `attended` when the line has no `mode:` (`Sources/ShelfRunnerCore/QueueLine.swift:116`).
- `ref`, `out`, `by` and the tick are **not** signed.

### Signatures

- HMAC-SHA256, key = the raw 32 key bytes, message = the UTF-8 canonical text, output lowercase
  hex (`Sources/ShelfRunnerCore/Protocol.swift:22-26`).
- A line's `sig:` is the first **8** hex characters (`Sources/ShelfRunnerCore/Protocol.swift:45`).
- A command's signature is the first **16** hex characters of the HMAC of
  `cmd|<verb>|<id or ->|<ts>` (`Sources/ShelfRunnerCore/Protocol.swift:81-83`).
- Comparison is constant time (`Sources/ShelfRunnerCore/Protocol.swift:56-66`).

### Start gate

Every line passes three checks, in this order (`Sources/ShelfRunnerCore/Security.swift:111-131`):

| Check | Fails as | Kind | Source |
|---|---|---|---|
| 1. signature (no key, no `sig:`, or no match) | `waiting:signature` | pending: checked again on every pass | `Security.swift:122` |
| 2. `out:` and `ref:` paths | `failed:path` | final | `Security.swift:123-124` |
| 3. approval for the id | `needs-approval` (a Run / Ignore notification is sent) | pending | `Security.swift:125-129`; `Agent.swift:154-159` |
| ignored id | `cancelled` | final | `Security.swift:127` |

Approval is recorded per id, by notification, CLI `approve`/`ignore` or a signed `run`/`ignore`
command (`Sources/ShelfRunnerCore/Security.swift:28-63`). After the gate come pause, the daily
limit, slots and resources ([7](#7-status), [12](#12-usage-limits))
(`Sources/ShelfRunnerCore/Supervisor.swift:182-205`).

**Exception.** `shelf-runner run <id>` is the local user's explicit action: it skips the signature,
the approval and every hold, but still refuses a ticked or already running line
(`Sources/ShelfRunnerCore/Runner.swift:89-102`). The signed `runnow` command does the same
(`Sources/ShelfRunnerCore/Bridge.swift:161-163`).

## 6. Pairing

- `shelf-runner pair` makes 32 random bytes with `SecRandomCopyBytes`
  (`Sources/ShelfRunnerCore/Security.swift:14-18`).
- It writes them to `pair.key` in the runner's state dir
  (`~/Library/Application Support/shelf-runner/`), mode 0600, through a temp file and `rename`
  (`Sources/ShelfRunnerCore/Security.swift:6`, `:19-23`, `Sources/ShelfRunnerCore/Paths.swift:16`).
  It is a file, not a Keychain item. A file that is not exactly 32 bytes counts as unpaired
  (`Sources/ShelfRunnerCore/Security.swift:8-11`).
- A new `pair` replaces the key at once; lines and commands signed with the old key stop verifying
  (`Sources/ShelfRunnerCore/Security.swift:4`, `:13`).
- It prints the pairing code on stdout and the `keyId` on stderr; the code is shown once
  (`Sources/shelf-runner/main.swift:123-130`).

**Pairing code.** `SR1-` + RFC 4648 base32 (`A-Z`, `2-7`), upper case, no padding: 52 characters
for 32 bytes (`Sources/ShelfRunnerCore/Protocol.swift:133-146`). A reader ignores case, spaces and
dashes, and accepts only a result of exactly 32 bytes (`Sources/ShelfRunnerCore/Protocol.swift:148-160`).
Example: `fixtures/protocol/v1/key.json`.

**keyId.** The first 8 hex characters of SHA-256 over the raw key
(`Sources/ShelfRunnerCore/Protocol.swift:19-20`). The status carries it, or `null` when unpaired
(`Sources/ShelfRunnerCore/StatusBuilder.swift:116`). A consumer compares it with its own key's id to
see whether it is paired with this runner.

**The other end** stores the key itself. The consuming app should keep it in its own secure storage;
the runner never sends the key anywhere.

## 7. Status

### Envelope

Name `dev.ted2xmen.shelf-runner.status`, `object: nil`, `deliverImmediately: true`, `userInfo`:

- `v`: integer, `1` (`Sources/ShelfRunnerCore/Bridge.swift:64`);
- `json`: the status as one compact JSON string, keys sorted
  (`Sources/ShelfRunnerCore/StatusV1.swift:165-170`).

The same JSON is written to `heartbeat.json` in the state dir after each send
(`Sources/ShelfRunnerCore/Bridge.swift:65`).

### When it is sent

- every 30 s, forced (`Sources/ShelfRunnerCore/Bridge.swift:29`, `:37-39`);
- on every ping, forced (`Sources/ShelfRunnerCore/Bridge.swift:69`);
- after every accepted state command and `attach`, forced (`Sources/ShelfRunnerCore/Bridge.swift:83`, `:87`);
- after an agent pass, only if something other than `seen` changed, and at most once per 2 s; a
  skipped change is sent when the 2 s window ends (`Sources/ShelfRunnerCore/Bridge.swift:36`, `:43-61`).

**Offline rule (recommendation).** Consumers SHOULD treat a status whose `seen` is more than 180 s
old as "runner offline". Both known consumers do this; that logic lives outside this repo. With a
forced send every 30 s, 180 s is six missed sends.

### Top level

All keys are always present; an unknown value is an explicit `null`, never a missing key
(`Sources/ShelfRunnerCore/StatusV1.swift:3`, `:144-151`).

**Waiting reasons**, a closed list (`Sources/ShelfRunnerCore/StatusV1.swift:158-160`): `memory`,
`disk`, `battery`, `thermal`, `limit`, `slot`, `folder`, `paused`, `signature`, `daily`. Consumers
should show any other reason as plain "waiting". Check order after the gate: `paused`, `daily`,
`slot`, `folder`, then the resources `memory`, `disk`, `battery`, `thermal`, `limit`
(`Sources/ShelfRunnerCore/Supervisor.swift:187-193`, `:266-283`). A resource reading that is unknown
never holds a job (`Sources/ShelfRunnerCore/Supervisor.swift:25`).

**`blocked`.** Only for an unattended Claude job: the number of `permission_denials` in its JSON
result, 0 included. `null` for attended jobs, Codex, jobs that have not ended, and unreadable
results. A denial does not change the state: exit 0 is still `done`
(`Sources/ShelfRunnerCore/PrintResult.swift:3-34`, `Sources/ShelfRunnerCore/Wrap.swift:45`, `:80`,
`Sources/ShelfRunnerCore/Agent.swift:205`).

### `now`, `asking` and `log`

The input is the last 12 lines of the live pane (plain `capture-pane`), or, when there is no live
window, the finished attended job's saved screen, or else the last 32 KB of its log file, cleaned
(`Sources/ShelfRunnerCore/StatusBuilder.swift:96-98`, `:138-152`).

- TUI furniture is removed first: Claude Code's input box, the user's status line, footer chrome,
  rules and key hints (`Sources/ShelfRunnerCore/Limits.swift:106-179`).
- **`now`**: a question (a line that ends in `?` after trimming frame glyphs) among the last 12
  meaningful lines wins; otherwise the last line with a letter or digit. At most 120 characters
  (`Sources/ShelfRunnerCore/Limits.swift:181-195`).
- **`asking`**: the job is attended and active, there was no log output for 60 s, and among the last
  6 lines (chrome removed) the last one ends in `?` or any one is an approval prompt such as
  `(y/n)`, `Do you want`, `Allow `, `❯ 1.` (`Sources/ShelfRunnerCore/Limits.swift:197-212`,
  `Sources/ShelfRunnerCore/StatusBuilder.swift:100`).
- **`log`**: the last 3 meaningful lines (`Sources/ShelfRunnerCore/StatusBuilder.swift:111`).

### Which jobs, and size limits

- Jobs of enabled folders only, never in the internal `scheduled` state; active and pending jobs
  always, final jobs only if they ended (or were last updated) in the last 24 h
  (`Sources/ShelfRunnerCore/StatusBuilder.swift:85-91`).
- Order: active, then pending, then final; newest start first within each
  (`Sources/ShelfRunnerCore/StatusBuilder.swift:86`, `:91-93`).
- At most 50 jobs, 3 log lines of 200 characters, `now` of 120 characters
  (`Sources/ShelfRunnerCore/StatusV1.swift:153-156`).
- The compact JSON stays under 16 KB. If it does not fit, all `log` arrays are emptied, then the
  oldest finished jobs are dropped, then jobs from the end of the list
  (`Sources/ShelfRunnerCore/StatusV1.swift:163`, `:172-187`). Nothing in the status says that jobs
  were dropped.

## 8. Ping

Any process can post `dev.ted2xmen.shelf.ping` with `object: "dev.ted2xmen.shelf"`. The runner
answers with a forced status broadcast, received by every observer, not only the one that pinged
(`Sources/ShelfRunnerCore/Protocol.swift:8`, `Sources/ShelfRunnerCore/Bridge.swift:69`). A ping
carries no signature and no version. A consumer pings when it starts, so it need not wait up to
30 s for the next status.

## 9. Commands

### Name

```text
dev.ted2xmen.shelf-runner.cmd.<verb>.<id or ->.<ts>.<sig16>
```

posted with `object: "dev.ted2xmen.shelf"` (`Sources/ShelfRunnerCore/Protocol.swift:11`, `:85-87`).
`<ts>` is Unix time in whole seconds (`Sources/ShelfRunnerCore/Bridge.swift:73`). `<id>` is a valid
`q-` or `s-` id; it is `-` for `pause` and `resume` and only for them
(`Sources/ShelfRunnerCore/Protocol.swift:95-96`, `:105-108`). Commands carry no protocol version.

### Verbs

The closed list is `run ignore stop requeue runnow pause resume log attach`
(`Sources/ShelfRunnerCore/Protocol.swift:71`). There is no `cancel`, `retry` or `ping` verb.

| Verb | Effect | Source |
|---|---|---|
| `run` | approve the id (`via: shelf`) | `Bridge.swift:137-146` |
| `ignore` | on a `failed:*` job: record `cancelled` for that run only, no approval written (a scheduled line's next occurrence still runs); otherwise record "ignore" for the id (a pending job becomes `cancelled` on the next pass) | `Bridge.swift:139-146`; `Security.swift:127` |
| `stop` | active job: Esc + Ctrl-C (pressed again if a stop is already pending; the grace clock keeps the first request), window closed after the grace time, `cancelled`; pending job: `cancelled` | `Bridge.swift:152-160`, `:120-128` |
| `requeue` | approve the id; if the job is final, set it to `queued` so it runs again | `Bridge.swift:147-151` |
| `runnow` | same as CLI `run <id>`: start now, skipping signature, approval and holds | `Bridge.swift:161-163`; `Runner.swift:89-102` |
| `pause`, `resume` | create or remove the `paused` file: no new starts while paused | `Bridge.swift:164-165`; `Agent.swift:216-225` |
| `log` | send a log reply ([10](#10-log-request-and-reply)); changes no state | `Bridge.swift:78-79` |
| `attach` | open the job in Terminal ([11](#11-attach)); changes no job state | `Bridge.swift:80-83` |

(Under `Sources/ShelfRunnerCore/`.) After `attach` and every state verb the runner sends a forced
status; state verbs also run an agent pass first (`Sources/ShelfRunnerCore/Bridge.swift:83-87`, `:172`).

### Gate

In this order (`Sources/ShelfRunnerCore/Protocol.swift:110-131`):

1. **Not paired**: refused (`Sources/ShelfRunnerCore/Bridge.swift:71`).
2. **Shape**: prefix, four dot-separated parts, known verb, integer `ts`, 16 hex characters for the
   signature, id rule above; else `malformed` (`Sources/ShelfRunnerCore/Protocol.swift:89-98`).
3. **Signature** over `cmd|verb|id|ts`, constant time; else `badSignature`
   (`Sources/ShelfRunnerCore/Protocol.swift:122-123`).
4. **Age**: `|now - ts| <= 60` s; else `stale` (`Sources/ShelfRunnerCore/Protocol.swift:113`, `:124`).
5. **Replay**: a `ts.sig` pair already accepted is refused; remembered pairs are pruned once more
   than 120 s old (`Sources/ShelfRunnerCore/Protocol.swift:125-129`).

A refused command is only written to the runner's log. There is no reply, success or failure
(`Sources/ShelfRunnerCore/Bridge.swift:74-75`). A producer learns the outcome from the next status.

Examples with the test key: `fixtures/protocol/v1/commands.json`.

## 10. Log request and reply

**Request**: the signed command `log` for a job id ([9](#9-commands)).

**Reply**: name `dev.ted2xmen.shelf-runner.log`, `object: nil`, `userInfo {v: 1, id, json}`
(`Sources/ShelfRunnerCore/Bridge.swift:114`).

- At most one reply per job per second; a request inside that second gets none
  (`Sources/ShelfRunnerCore/Bridge.swift:96`).
- A job id the runner has no record of gets no reply (`Sources/ShelfRunnerCore/Bridge.swift:97`).

**Where the lines come from**, first match wins:

1. An active job with a live window: `tmux capture-pane -p -J -e -t <window> -S -500`, colours kept
   as `styles` (`Sources/ShelfRunnerCore/Bridge.swift:100-105`, `Sources/ShelfRunnerCore/Tmux.swift:138-146`).
2. A finished attended job: its last saved screen, plain (`Sources/ShelfRunnerCore/Bridge.swift:106-110`).
3. Otherwise the last 512 KB of the job's log file, control sequences removed; when the read starts
   mid-file, the first partial line is dropped and `truncated` is true
   (`Sources/ShelfRunnerCore/LogReply.swift:20`, `:26-32`, `:86-99`,
   `Sources/ShelfRunnerCore/LogTail.swift:17-29`). A job that never started answers with no lines.

Empty lines are dropped and lines are trimmed (`Sources/ShelfRunnerCore/LogTail.swift:10-15`).

**JSON** (`Sources/ShelfRunnerCore/LogReply.swift:4-13`):

| Key | Type | Meaning |
|---|---|---|
| `id` | string | job id |
| `at` | string | ISO time of the reply |
| `state` | string | the job's state |
| `lines` | array of string | oldest first, at most 200, each at most 400 characters |
| `truncated` | bool | older lines exist that are not here, or a line was cut |
| `styles` | array, optional | only for a live window, below |

**Size.** The whole `json` string is at most 16 KB. The oldest lines are dropped until it fits
(`Sources/ShelfRunnerCore/LogReply.swift:15-18`, `:36-55`). Producers of replies must stay within
16 KB. A consumer may accept a larger reply leniently.

**`styles`.** One array per entry of `lines`, same order; each run is `[start, len, fg, bg, flags]`;
`[]` for a line without colour; the key is left out when no line has a run
(`Sources/ShelfRunnerCore/LogReply.swift:11-13`, `:56-84`).

- `start` and `len` count Unicode scalars of the line as it appears in `lines`; the 400-character
  cut counts Characters, and runs are clipped to the scalars it keeps
  (`Sources/ShelfRunnerCore/LogReply.swift:57-60`, `Sources/ShelfRunnerCore/AnsiText.swift:148-156`).
- `fg`, `bg`: `-1` default, `0...255` palette, `>= 256` truecolor `256 + (r<<16 | g<<8 | b)`;
  `flags`: 1 bold, 2 dim, 4 italic, 8 underline, 16 inverse
  (`Sources/ShelfRunnerCore/AnsiText.swift:6-14`, `:81-92`).
- Runs are in order, never overlap, at most 24 per line
  (`Sources/ShelfRunnerCore/AnsiText.swift:94-95`, `:120-146`).
- `lines` and `truncated` are computed as if there were no `styles`. If the reply then exceeds
  16 KB, the oldest lines' runs become `[]`, and if it still does not fit the key is dropped
  (`Sources/ShelfRunnerCore/LogReply.swift:64-84`).

Examples: `fixtures/protocol/v1/log-reply.json` (with `styles`) and `log-reply-plain.json` (without).

## 11. Attach

On a valid `attach` command (`Sources/ShelfRunnerCore/Attach.swift:11-39`):

1. If the job is not active, or its tmux session does not exist, the runner sets
   `attachError: "no-session"` and stops there. The job state does not change.
2. Otherwise it writes `attach/<id>.command` in the state dir, mode 0700
   (`Sources/ShelfRunnerCore/Paths.swift:25-26`, `:36`). The script unsets `TMUX`, runs
   `select-window -t '=<session>:<id>'` (only if the job's window is alive), then
   `exec tmux attach-session -t '=<session>'`. Only the runner's tmux path, socket, session and job
   id go in, each single-quoted; never task text (`Sources/ShelfRunnerCore/Tmux.swift:152-161`).
3. It opens the file with `open -a Terminal` (`Sources/ShelfRunnerCore/Attach.swift:41-44`). On
   success it sets `attached` to the current ISO time. If Terminal cannot be opened, neither field
   is set (`Sources/ShelfRunnerCore/Attach.swift:36-38`).
4. It sends a forced status (`Sources/ShelfRunnerCore/Bridge.swift:83`).

`attached` and `attachError` are kept in memory and appear only while the job is active. When the
job is no longer active, both and the `.command` file are removed
(`Sources/ShelfRunnerCore/Attach.swift:46-54`, `Sources/ShelfRunnerCore/Agent.swift:135`).

A consumer that sees neither field change may fall back to its own action after a short timeout
(for example 3 s). That is consumer behavior, outside this repo.

## 12. Usage limits

- **Claude Code** reports limits to its status line command on stdin. If that command is
  `shelf-runner limits-tee | <your command>`, the runner saves the JSON to `claude-limits.json` in
  the state dir and passes the same bytes on; `--show` prints a short line instead
  (`Sources/shelf-runner/main.swift:54-60`, `Sources/ShelfRunnerCore/Limits.swift:74-94`). It reads
  `rate_limits.five_hour` and `rate_limits.seven_day` (`used_percentage`, `resets_at`)
  (`Sources/ShelfRunnerCore/Limits.swift:21-33`).
- **Codex**: the newest `~/.codex/sessions/**/rollout-*.jsonl`, the last `rate_limits` in its last
  256 KB, windows of 300 and 10080 minutes. This format is undocumented
  (`Sources/ShelfRunnerCore/Limits.swift:35-67`).
- Either source counts only if its file changed in the last 15 minutes; a stale source is left out
  of `limits` (`Sources/ShelfRunnerCore/Limits.swift:8`, `:24`, `:44`).
- **Hold**: a new job waits as `waiting:limit` while its agent's `fiveHour` is at or above
  `limit_percent` (default 90) (`Sources/ShelfRunnerCore/Supervisor.swift:16`, `:280-281`). After
  `limit_wait_minutes` (default 90) in `waiting:limit` the job starts anyway, with a notification
  (`Sources/ShelfRunnerCore/Supervisor.swift:17-18`, `:193-200`).

## 13. tmux names

- **Server**: the user's default tmux server, unless config `[tmux] socket` is set, which adds
  `-L <socket>` to every call (`Sources/ShelfRunnerCore/Config.swift:10-12`, `:68`,
  `Sources/ShelfRunnerCore/Tmux.swift:69`).
- **Session**: `shelf-<folder basename>`, every character other than ASCII letters, digits, `-` and
  `_` replaced with `_`; `shelf-root` for an empty name (`Sources/ShelfRunnerCore/Tmux.swift:59-64`).
  A new session is 200 x 50 (`Sources/ShelfRunnerCore/Tmux.swift:91`).
- **Window**: named after the job id, automatic rename off
  (`Sources/ShelfRunnerCore/Runner.swift:120-121`, `Sources/ShelfRunnerCore/Tmux.swift:122-125`).
  The status `tmux` field is `<session>:<job id>` (`Sources/ShelfRunnerCore/StatusBuilder.swift:106`).
- **Targets** use `=` for an exact match, so `shelf-a` never matches `shelf-ab`
  (`Sources/ShelfRunnerCore/Tmux.swift:66-67`).

Two folders with the same basename share a session; their windows still differ by job id.

Runner Desk (outside this repo, see its
[README](https://github.com/Ted2xmen/runner-desk)) opens its own grouped `view-<id>` session on the
runner's session for each job it shows, so its views never change the runner's windows. It also
keeps its own terminals on a separate tmux server (`-L runner-desk`) and may add `term-*` grouped
sessions on the runner's server (UNVERIFIED: these last two points are not checked against Runner
Desk's code here).

## 14. Notification click

The runner's macOS notifications have the id `<kind>:<job id>`, kind `approve`, `info` or `ask`
(`Sources/ShelfRunnerCore/Notices.swift:3-22`). An `approve` notification has Run and Ignore buttons,
recorded as an approval `via: notification` (`Sources/shelf-runner/AppNotifier.swift:34-37`, `:58-59`,
`Sources/shelf-runner/main.swift:216-224`).

A click on the notification itself (`Sources/shelf-runner/AppNotifier.swift:60-77`,
`Sources/ShelfRunnerCore/Notices.swift:76-94`):

1. if an app handles `runnerdesk://job/<id>`, that URL is opened (`runnerdesk://` when the id is
   unknown);
2. else, if the app with bundle id `dev.ted2xmen.shelf` is installed, it is opened (no URL; it has no
   URL scheme);
3. else nothing happens.

## 16. Known gaps

Facts from the code, not fixed here:

1. **Nothing can sign a scheduled line today.** `shelf-runner line` only emits queue (`q-`) lines
   (`Sources/shelf-runner/main.swift:136-151`, `Sources/ShelfRunnerCore/Security.swift:143-162`), and
   the other end currently writes only queue lines. A scheduled line therefore stays in
   `waiting:signature` unless someone computes the HMAC by hand.
2. **The fixture README frontmatter is hard-coded** in the generator (`created_by`, `created`,
   `updated` dates) and does not change on regeneration
   (`Tests/ShelfRunnerCoreTests/ProtocolFixtureTests.swift:118-130`).
3. **Status and log replies are not authenticated.** Any process can post a notification named
   `dev.ted2xmen.shelf-runner.status` or `.log`; a consumer cannot tell it from the runner's
   (`Sources/ShelfRunnerCore/Bridge.swift:19-21`, `:64`, `:114`).
4. **Commands get no acknowledgement.** A refused or lost command looks the same to the producer
   (`Sources/ShelfRunnerCore/Bridge.swift:74-75`). A `log` request inside the 1 s window also gets
   no reply (`Sources/ShelfRunnerCore/Bridge.swift:96`).
5. **The status does not say it was cut.** The 16 KB clamp drops log lines and jobs without a flag
   (`Sources/ShelfRunnerCore/StatusV1.swift:172-187`).
6. **`slots.running` and `jobs` can disagree.** `running` counts active records of all folders,
   disabled ones included, while `jobs` lists enabled folders only
   (`Sources/ShelfRunnerCore/StatusBuilder.swift:88`, `:115`).
7. **`scheduled` lists every valid line**, signed or not, approved or not, with no state per row
   (`Sources/ShelfRunnerCore/StatusBuilder.swift:124-136`).
8. **Fixture `waitMaxMin` is always 90.** The generator uses the default; a running runner sends the
   configured `limit_wait_minutes` (`Tests/ShelfRunnerCoreTests/ProtocolFixtureTests.swift:209`,
   `Sources/ShelfRunnerCore/StatusBuilder.swift:110`).
9. **Command signatures are case-insensitive on input.** The parser accepts upper-case hex and
   lowercases it, although producers emit lowercase (`Sources/ShelfRunnerCore/Protocol.swift:94`, `:97`).
10. **Approval is per id, not per content.** An approved id stays approved if its line is edited and
    signed again (`Sources/ShelfRunnerCore/Security.swift:125`). Only a key holder can make that new
    signature.
11. **"Whitespace" in the canonical title is Unicode White_Space**, while the line tokenizer splits
    only on space and tab (`Sources/ShelfRunnerCore/Protocol.swift:32`,
    `Sources/ShelfRunnerCore/QueueLine.swift:101`). An independent implementation must use the same
    definition to get the same signature.
12. **The fixture README says the other end copies the files byte for byte**, but no tooling keeps
    copies in sync ([15](#15-fixtures)) (`Tests/ShelfRunnerCoreTests/ProtocolFixtureTests.swift:6`, `:321`).
